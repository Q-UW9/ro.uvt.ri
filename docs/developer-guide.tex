\section{Project Overview}
% ──────────────────────────────────────────────────────────────────────────────

This project follows a \textbf{Headless CMS} architecture:

\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Backend (CMS):} WordPress -- used exclusively for content
          management via the REST API. Each developer runs a local instance.
    \item \textbf{Frontend:} React (Vite + TypeScript) -- the actual website
          that end-users interact with. It consumes the WordPress REST API.
\end{itemize}

\subsection{Repository Structure}

\begin{lstlisting}
ro.uvt.ri/
|-- .gitignore          # Ignores WP core, node_modules, env files
|-- .wp-env.json        # WordPress environment configuration
|-- README.md           # Quick-start instructions
|-- docs/               # This guide and other documentation
|   +-- developer-guide.tex
+-- frontend/           # React application (Vite + TypeScript)
    |-- package.json
    |-- src/
    |   |-- App.tsx
    |   |-- api/wordpress.js
    |   +-- pages/
    +-- vite.config.ts
\end{lstlisting}

\begin{warningbox}
The \texttt{wordpress/} folder on your local machine is \textbf{not tracked by Git}.
Each developer sets up their own local WordPress instance using
\texttt{wp-env} (Docker) or a local server stack such as Laragon or XAMPP.
\end{warningbox}

\section{Prerequisites}
% ──────────────────────────────────────────────────────────────────────────────

Before cloning the repository, make sure the following tools are installed:

\begin{enumerate}[leftmargin=1.5em]
    \item \textbf{Git} --
          \url{https://git-scm.com/downloads}
    \item \textbf{Node.js} (v18 or newer, LTS recommended) --
          \url{https://nodejs.org/}
    \item \textbf{Docker Desktop} (required for \texttt{wp-env}) --
          \url{https://www.docker.com/products/docker-desktop/}
\end{enumerate}

\begin{tipbox}
If you prefer not to use Docker, you can use \textbf{Laragon} (Windows)
or \textbf{MAMP/XAMPP} instead. See Section~\ref{sec:alt-wp} for the
alternative WordPress setup.
\end{tipbox}

% ──────────────────────────────────────────────────────────────────────────────
\section{Initial Setup (First Time Only)}
% ──────────────────────────────────────────────────────────────────────────────

\subsection{Step 1 -- Clone the Repository}

\begin{lstlisting}
git clone https://github.com/Q-UW9/ro.uvt.ri.git
cd ro.uvt.ri
\end{lstlisting}

\subsection{Step 2 -- Start WordPress (via wp-env + Docker)}
\label{sec:wp-env-setup}

Make sure \textbf{Docker Desktop is running}, then execute:

\begin{lstlisting}
npm -g install @wordpress/env
wp-env start
\end{lstlisting}

This will:
\begin{itemize}[leftmargin=1.5em]
    \item Download the WordPress core automatically.
    \item Create a local MySQL database inside Docker.
    \item Expose WordPress at \texttt{http://localhost:8888}.
    \item Provide an admin dashboard at \texttt{http://localhost:8888/wp-admin/}
          (default credentials: \texttt{admin} / \texttt{password}).
\end{itemize}

\subsection{Step 3 -- Install Frontend Dependencies}

\begin{lstlisting}
cd frontend
npm install
\end{lstlisting}

\subsection{Step 4 -- Configure the API Connection}

Create a \texttt{.env.local} file inside the \texttt{frontend/} directory:

\begin{lstlisting}
# frontend/.env.local
VITE_WP_API_URL=http://localhost:8888/wp-json
\end{lstlisting}

\begin{warningbox}
The \texttt{.env.local} file is \textbf{not tracked by Git} (it is listed
in \texttt{.gitignore}). Each developer must create their own copy.
\end{warningbox}

\subsection{Step 5 -- Start the React Development Server}

\begin{lstlisting}
npm run dev
\end{lstlisting}

The React application will start at \texttt{http://localhost:5173}. \\
You can now open both URLs side by side:

\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Add content:}
          \texttt{http://localhost:8888/wp-admin/}
    \item \textbf{View the website:}
          \texttt{http://localhost:5173}
\end{itemize}

% ──────────────────────────────────────────────────────────────────────────────
\section{Alternative: WordPress via Laragon / XAMPP}
\label{sec:alt-wp}
% ──────────────────────────────────────────────────────────────────────────────

If Docker is not available, you can set up WordPress manually:

\begin{enumerate}[leftmargin=1.5em]
    \item Download WordPress from
          \url{https://wordpress.org/download/}.
    \item Extract it into your local server's web root
          (e.g., \texttt{C:\textbackslash laragon\textbackslash www\textbackslash ro.uvt.ri}).
    \item Create a MySQL database
          (e.g., \texttt{ro\_uvt\_ri}) using phpMyAdmin or HeidiSQL.
    \item Copy \texttt{wp-config-sample.php} to \texttt{wp-config.php}
          and update the database credentials:
\end{enumerate}

\begin{lstlisting}
define( 'DB_NAME',     'ro_uvt_ri' );
define( 'DB_USER',     'root' );
define( 'DB_PASSWORD', '' );
define( 'DB_HOST',     'localhost' );
\end{lstlisting}

\begin{enumerate}[leftmargin=1.5em, resume]
    \item Open \texttt{http://ro.uvt.ri.test/wp-admin/} in your browser
          to complete the WordPress installation wizard.
    \item Update \texttt{frontend/.env.local} to point to your local URL:
\end{enumerate}

\begin{lstlisting}
VITE_WP_API_URL=http://ro.uvt.ri.test/wp-json
\end{lstlisting}

\section{Daily Workflow}
% ──────────────────────────────────────────────────────────────────────────────

\subsection{Starting a Work Session}

\begin{lstlisting}
# 1. Pull the latest changes
git pull origin main

# 2. Start the WordPress backend (Docker method)
wp-env start

# 3. Start the React frontend
cd frontend
npm run dev
\end{lstlisting}

\subsection{Creating a Feature Branch}

Always work on a dedicated branch -- never commit directly to \texttt{main}:

\begin{lstlisting}
# Create and switch to a new branch
git checkout -b feature/your-feature-name

# ... make your changes ...

# Stage and commit
git add .
git commit -m "feat: describe your change"

# Push the branch to GitHub
git push origin feature/your-feature-name
\end{lstlisting}

Then open a \textbf{Pull Request} on GitHub to merge into \texttt{main}.

\subsection{Keeping Up to Date}

Before starting new work, always synchronize with the latest \texttt{main}:

\begin{lstlisting}
# Switch to main and pull the latest
git checkout main
git pull origin main

# Switch back to your feature branch and rebase
git checkout feature/your-feature-name
git rebase main
\end{lstlisting}

\begin{tipbox}
If new dependencies were added by a teammate, you may need to re-run
\texttt{npm install} inside the \texttt{frontend/} directory after
pulling.
\end{tipbox}

\subsection{Ending a Work Session}

\begin{lstlisting}
# Stop the WordPress backend (Docker method)
wp-env stop
\end{lstlisting}

\section{Troubleshooting}
% ──────────────────────────────────────────────────────────────────────────────

\subsection{``Permission Denied'' on Windows}

If Git reports \texttt{dubious ownership} errors:
\begin{lstlisting}
git config --global --add safe.directory 'D:/path/to/ro.uvt.ri'
\end{lstlisting}

\subsection{Port Conflicts}

If port 8888 or 5173 is already in use:
\begin{itemize}[leftmargin=1.5em]
    \item For WordPress: edit \texttt{.wp-env.json} and add a custom port
          mapping.
    \item For React: Vite will automatically try the next available port
          (5174, 5175, etc.).
\end{itemize}

\subsection{CORS Errors When Fetching from WordPress}

Install and activate the
\href{https://wordpress.org/plugins/wp-graphql/}{WP GraphQL} or a CORS
plugin on your local WordPress instance. Alternatively, configure the
Vite proxy in \texttt{frontend/vite.config.ts}:

\begin{lstlisting}
// vite.config.ts
export default defineConfig({
  server: {
    proxy: {
      '/wp-json': 'http://localhost:8888'
    }
  }
})
\end{lstlisting}
