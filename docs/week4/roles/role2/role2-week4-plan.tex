and no coordination with other roles took place. Every deliverable from Week 3 is now a
carry-over.

Card, AccordionSection, TabsSection, SectionHeader, PageLayout, ContentGrid --- has never

has never been reviewed for user-flow alignment.

anywhere in the project. These validations must happen at the start of Week 4 before any
new components or pages are built.

\section{Carry-Over Documents to Produce}
% ==========================================================

All five of these were due in Week 3. They must be produced before new Week 4 work begins.

% ----------------------------------------------------------
\subsection{\texttt{ux-validation-week3.md}}
% ----------------------------------------------------------

Per-component UX review covering all Week 3 built components. For each component:

\begin{itemize}
    \item Component name and file path
    \item What it is supposed to do
    \item Whether it serves its intended purpose based on \texttt{02\_User\_Flows.md}
    \item Specific issues found (if any)
    \item Pass / Needs revision verdict
\end{itemize}

% ----------------------------------------------------------
\subsection{\texttt{route-hierarchy-corrections.md}}
% ----------------------------------------------------------

List any corrections needed to the proposed route structure based on user journey analysis.
Cross-reference \texttt{01\_Sitemap.md} and \texttt{02\_User\_Flows.md}. Flag:

\begin{itemize}
    \item Routes that are missing
    \item Route groupings that do not match user mental models
    \item Navigation paths that are too deep or have wrong parent-child relationships
\end{itemize}

% ----------------------------------------------------------
\subsection{\texttt{navigation-consistency-feedback.md}}
% ----------------------------------------------------------

Review the Navbar labels and structure against the sitemap. Specifically flag the mismatch
between the current Navbar labels (About, Admissions, Erasmus, Research, Contact) and the
sitemap top-level routes. Provide corrected label recommendations.

% ----------------------------------------------------------
\subsection{\texttt{page-template-alignment-feedback.md}}
% ----------------------------------------------------------

For each page type in the sitemap (homepage, section landing page, listing page, detail
page, contact page), specify:

\begin{itemize}
    \item What user goal the page must serve
    \item What components it should contain to serve that goal
    \item Whether the current template structure (PageLayout + ContentGrid) is sufficient
    \item What is missing
\end{itemize}

This document feeds directly into Role 5's InnerPageTemplate and HomePageTemplate work.

% ----------------------------------------------------------
\subsection{\texttt{wordpress-structure-user-flow-feedback.md}}
% ----------------------------------------------------------

For Role 6. Review the planned CPT and taxonomy structure from a user perspective:

\begin{itemize}
    \item Which CPTs are clearly needed and why
    \item Whether the \texttt{people} CPT is necessary for Week 4 or can be deferred (provide UX reasoning)
    \item Whether the taxonomy filtering model supports how users actually search for programmes and resources
    \item Any content planned as a CPT entry that would be better as a static WP Page, or vice versa
\end{itemize}
